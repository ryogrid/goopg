## Root cause hypothesis for Q14 fusion bug

Q14 is a TPC-DS query with a hash join chain. The fusion operator
(tryFuseHashCascade) fuses consecutive binary HashJoin nodes into a
single fusedHashJoinOp. The 100 vs 200 row discrepancy (exactly half)
suggests a duplicate-elimination or key-collision bug in the fused
operator — possibly the fused hash lookup is dropping rows when the
same hash key appears in multiple levels of the cascade.

- The fusion code stays in-tree but is never enabled
- M0126-0007 is COMPLETE — "leave the switch off permanently" is a
  legitimate recorded completion per the task spec
