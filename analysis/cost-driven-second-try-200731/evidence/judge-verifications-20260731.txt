V4 — VirtualSlot.Materialize() does not clone arena-backed Datums
================================================================================
internal/executor/slot.go:159-169

    func (s *VirtualSlot) Row() Row {
        out := acquireRow(len(s.cols))
        for i := range s.cols { out[i] = s.Get(i) }
        return out
    }
    func (s *VirtualSlot) Materialize() *MaterializedSlot {
        return &MaterializedSlot{schema: s.schema, row: s.Row()}
    }

RESULT: CONFIRMED — `Materialize()` copies Datum structs but does NOT call
cloneRowOwned, so an arena-backed Datum keeps its ArenaID and dangles after the
producer's next arena Reset. Contrast drainRowsBounded (V5), which does exactly
that clone and documents why. Any slot-chaining work (Stage 0a-legacy / Stage 1)
must treat this as a prerequisite fix, not a detail.

================================================================================
V5 — drainRowsBounded deep-copies, and the copy is REQUIRED
================================================================================
internal/executor/spill.go:384-402

    // M0073-0004 retention boundary: arena-backed Datums must be promoted to
    // owned []byte before we accumulate, since the producer's next Next may
    // trigger arena.Reset and invalidate the previous page's bytes.
    var dup Row
    if rowHasArena(row) { dup = cloneRowOwned(row) } else { dup = make(Row, len(row)); copy(dup, row) }
    rows = append(rows, dup)

RESULT: CONFIRMED. The first draft of contract C13 told implementers NOT to copy
build rows. That instruction would have introduced a silent corruption bug. C13
now says the opposite, in bold. Retained as R15.
