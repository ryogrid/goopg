# 4. ROOT CAUSE — the boundary map is a rotation, and the tripwire cannot see it
# ---------------------------------------------------------------------------
# Minimal reproducer (2 relations, 1 join predicate, 1 restriction), run against
# the same SF1 cluster on a fresh server per arm:
#
#     select * from orders, customer where o_custkey = c_custkey and o_orderkey = 1;
#
# FLAG OFF — correct. FLAG ON — every value is one position off from its name:
#
#     o_orderdate     | asymptotes wake furiously even theodolites. …   <- o_comment
#     o_orderkey      | 1994-11-01 00:00:00.000000                      <- o_orderdate
#     o_custkey       | 1                                               <- o_orderkey
#     o_orderpriority | 113413                                          <- o_custkey
#     o_shippriority  | 1-URGENT                                        <- o_orderpriority
#     o_clerk         | 0                                               <- o_shippriority
#     o_orderstatus   | Clerk#000000222                                 <- o_clerk
#     o_totalprice    | F                                               <- o_orderstatus
#     o_comment       | 348873.6                                        <- o_totalprice
#     c_custkey       | bold regular accounts beneath the slyly …       <- c_comment
#     c_mktsegment    | 113413                                          <- c_custkey
#     c_nationkey     | AUTOMOBILE                                      <- c_mktsegment
#     c_name          | 20                                              <- c_nationkey
#     c_address       | Customer#000113413                              <- c_name
#     c_phone         | R9QgXprT1ZPE6EgGjEt                             <- c_address
#     c_acctbal       | 892-501-7595                                    <- c_phone
#     c_comment       | 9704.93                                         <- c_acctbal
#
# The value sequence is the name sequence ROTATED BY ONE, per relation. The
# names come from star expansion against the PRE-search binding schema; the
# values come through the boundary `Project`. So the two disagree by exactly the
# map the boundary applied.
#
# Its plan (flag ON) shows why this query and not others:
#
#     Hash Join (INNER)  Hash Cond: (customer.c_custkey = orders.o_custkey)
#       ->  Seq Scan on public.customer
#       ->  Seq Scan on public.orders   Filter: (o_orderkey = 1)
#
# The search chose `customer` as the outer, so the root layout is NOT binding
# order, `boundaryMapIsIdentity` is false, and `projectToBindingOrder`
# (internal/planner/createplanroot.go:240) fires. **That is the discriminator
# for the whole sweep**: a query whose winning tree is already left-deep in
# binding order takes the identity early-return and is unaffected; a query whose
# winner reorders the leaves gets the rotation. It explains why Q1/Q4/Q6/Q11/
# Q13/Q14/Q16 are untouched and Q2/Q5/Q7/Q8/Q9/Q10/Q12/Q17 are not.
#
# `projectToBindingOrder` is self-consistent — it takes `in[m[bind]]` for both
# the datum and the schema entry — so the defect is UPSTREAM of it, in the
# `outputLayout` that `createPlanNode` returns for the winning join arm
# (internal/planner/createplanjoin.go: `createHashJoinPlan` / `createMergeJoinPlan`
# / `createNestLoopPlan`, and `baseRelLayout`). `boundaryMap`'s three documented
# failure modes — HOLE, OUT OF RANGE, DUPLICATE — are all detected by checking
# that the map is a permutation of [0,width). **A rotation passes all three.**
# The tripwire 03 §10 installed against the M0097-0058 class is therefore blind
# to the one instance of that class the search actually produced.
#
# Why EXTRACT is the only thing that ERRORS: it is the only construct in TPC-H
# that type-checks its argument at run time. Q7/Q8/Q9 are exactly the three
# queries with `extract(year from <date column>)` in the select list; they get a
# text column instead and raise 42883. Every other query takes the same
# corruption SILENTLY. The three errors are not three bugs — they are the only
# three places the one bug is loud.
#
