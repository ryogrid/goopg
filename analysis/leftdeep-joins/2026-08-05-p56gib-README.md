# M0127-P5.6-g-i-b — a plan-shape channel for the TPC-DS SF0.5 gate

Date 2026-08-05. Tree `b2d82285` (Go code identical to `f8338a09`; the two
commits since are docs and CI logs — `git diff --stat f8338a09 HEAD -- '*.go'`
is empty, which is what makes the D row below a controlled comparison).

## Why

P5.6-g-i measured that commit `4b820ab8` re-ordered **74 of 99** TPC-DS plans
while the SF0.5 gate reported a verdict identical to the previous baseline line
for line (`PASS=94`, the same 57 checksums, the same single Q47 TIMEOUT). The
gate compares row counts and value checksums; it is blind to plan shape. For a
milestone whose subject is the join search, that is the one event the artefact
should not miss. Design doc 09 §5.11.

## What landed

- `scripts/tpcds-plan-diff.py` — per-query diff of two plan captures. Prints
  `=== PLAN-SHAPE: queries=N same=N changed=N added=N removed=N ===` and the
  changed query list; `--verbose` adds a unified diff per query; `--strict`
  exits 1 when anything moved (the gate does not use `--strict`).
- `scripts/tpcds-sf05-regression.sh`:
  - `plans` subcommand — capture + diff on its own, **14 s** for all 99;
  - a tail stage on `sweep` writing `plans-<stamp>.txt` beside
    `sweep-<stamp>.txt` and appending the diff to the report;
  - `SF05_NO_PLANS=1`, `PLAN_TIMEOUT`, `SF05_PLANS_BASELINE` (`none` to skip
    the diff; a path to attribute a change to a specific commit);
  - `sf05_planner_flags_line` factored out so the capture stamps the same arm
    label as the report.

## The primary bar is not weakened

Nothing in the channel can fail the gate. Verified directly, not asserted:

    $ QUERIES="42" PLAN_DIFF=/nonexistent/diff.py …/tpcds-sf05-regression.sh sweep
    sweep rc=0

The report carries the python error and the line
`# The plan channel is NON-BLOCKING: it never changes this gate's exit status.`

## Bar: two consecutive captures at one commit, one at another

**Same commit, three consecutive captures → `changed=0` each time.**
(`plans-20260805-061634`, `-061705`, and the one written by the `QUERIES="3 42"`
sweep at `-061857`.) `EXPLAIN` without `ANALYZE` emits no timings and no actual
rows, so the file is byte-stable; P5.6-g-i had measured the same floor.

**Different commits → exactly the expected set.** The capture format is
deliberately identical to the hand-rolled `2026-08-05-p56gi-capture.sh`, so that
loop's four committed corpus captures are valid baselines. The new gate path's
capture at `b2d82285` diffs against them as:

| baseline | changed | expected |
|---|---|---|
| D `f8338a09` | 0 | 0 — same engine code, different harness + directory |
| C `8ce056ff` | 4 — Q13 Q41 Q48 Q85 | the P5.6-g-iv set, exactly |
| B `4b820ab8` | 5 — + Q83 | + the P5.6-g set |
| A `ce027cee` | 75 | the P5.6-g-i A→D net |

Reproduce (no server needed — the captures are committed):

    python3 scripts/tpcds-plan-diff.py \
      analysis/leftdeep-joins/2026-08-05-p56gi-plans-C-8ce056ff.txt \
      analysis/leftdeep-joins/2026-08-05-p56gi-plans-D-f8338a09.txt

## The one real defect this found

The D row initially reported **3** changed — Q36, Q70, Q86, the dsqgen artefacts
that fail to parse (on upstream PG too), so their block is an error message
rather than a plan. psql stamps errors with the *path* of the script it was
reading, and the new harness writes its EXPLAIN script inside the results dir
while the predecessor used `/tmp`:

    -psql:/tmp/ds05_explain_all.sql:29: ERROR:  syntax error at or near …
    +psql:/home/ryo/…/tpcds-results-sf05/.explain_all.sql:29: ERROR:  syntax error …

Three permanent false positives in a channel whose entire value rests on a zero
noise floor — and they would have fired on any run with `SF05_RESULTS_DIR`
redirected. `tpcds-plan-diff.py` canonicalises the prefix to
`psql:<script>:<line>:`, keeping the line number (it moves only when the query
file does).

## Scope

goopg-against-goopg over time: "did this commit move a plan?", not "is the plan
PG's". The latter is 09 §4's per-joinrel parity instrument, which needs the PG
oracle; this one runs on the SF0.5 cluster alone in 14 s.

## Not committed

The plan captures themselves (~512 KB each) stay out of git — they are
reproducible in 14 s and `plans-*.txt` is already gitignored under
`bench/tpcds/runtime_goopg/tpcds-results-sf05/`. The four P5.6-g-i corpus
captures remain the committed reference baselines.
