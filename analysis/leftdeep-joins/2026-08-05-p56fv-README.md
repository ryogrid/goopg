# P5.6-f-v — the DS05 sweep diffs the TIMEOUT set, not its cardinality

2026-08-05. Successor to P5.6-f-iii (§5.15): a 17× re-pricing of Q47 hid behind
**four byte-identical SUMMARY lines**, because `TIMEOUT=1` is invariant to
*which* query timed out. Design write-up:
[09 §5.16](../../docs/design/leftdeep-joins/09-verification-and-acceptance.md).

## What landed

- `scripts/tpcds-sweep-diff.py OLD NEW [--min-secs N] [--factor F] [--strict]`
- `scripts/tpcds-sf05-regression.sh delta [OLD [NEW]]` — the channel on its own;
  runs nothing, needs no server, defaults to the two newest reports
- a `sweep` tail stage directly under the SUMMARY (before the slower plan pass),
  skippable with `SF05_NO_DELTA=1`, baseline overridable with
  `SF05_SWEEP_BASELINE=<path|none>`

The input is the **sweep report itself** — the format `cmd_sweep` already
prints — so no new artefact exists and every archived report is a baseline.
Non-blocking: rows and checksums remain the only thing that can fail the gate.

## The pair the channel exists for

`sweep-20260804-214607` → `sweep-20260804-232914`. Both report
`… ERROR=0 TIMEOUT=1 SKIP=4`, byte-identical:

```
PASS       +Q72  -Q47
TIMEOUT    +Q47  -Q72
SLOWER     Q57 15s->81s (5.4x)  Q52 2s->5s (2.5x)
FASTER     Q96 18s->1s (0.1x)  Q99 10s->1s (0.1x)  Q50 14s->2s (0.1x)  …
=== STATUS-DELTA: compared=99 verdict-changes=yes runtime-moves=20 (>=2.0x, floor 5s, TIMEOUT readings excluded) ===
```

Both §5.15 victims — the traded timeout **and** Q57's 5.4× — named out of
artefacts that already existed the night `ce027cee` landed. Finding them
originally cost a cluster copy, a worktree per commit and a bisect.

## Replay result

87 adjacent pairs, zero crashes, zero parse failures, **17 pairs report a
verdict change**. The corpus spans 4-column oracles, subset probes, `FORCE=1`
runs, ERROR lines and two `TIMEOUT_SEC` regimes; every comparability hazard the
tool cannot resolve is printed as a `NOTE:` line rather than silently absorbed.

## Live run

`sweep-20260805-090258` at `f05b5329` (harness-only commit, no Go source
touched): `PASS=94 (57 ck-verified, 37 ck=n/a) MISMATCH=0 CKMISMATCH=0 ERROR=0
TIMEOUT=1 SKIP=4`, delta `verdict-changes=none`, one runtime move (Q83 7 s →
3 s, host noise above the 5 s floor). Baseline selection was exercised too: the
newest report at the time was a `QUERIES=1 3 92` probe and the picker correctly
skipped it for the newest **full** report.

## Deliberately not done

- **Adjacent runs only.** Creep that stays under 2× per run is unnamed.
- **Still cannot fail the gate.** A traded timeout is now impossible to miss in
  the report, but making one fatal needs a curated per-query budget file — not
  filed while the timeout set is still moving under active planner work
  (P5.6-f-iv is open, and it is the fix for Q47/Q57).
