Per-suite status counts are derived from `docs/test-port/postgres-oracle-target-inventory.csv`
(the authoritative per-spec inventory); this tool only renders that CSV and never rewrites it.

Notes on the columns below:
- For the `*-tap` suites (`recovery-tap`, `subscription-tap`, `client-tools-tap`), a row with
  `status=port, pass_required=yes` (a ported TAP test that must always pass) is counted under
  BOTH `port` and `pass` — so for those three suites the status columns no longer sum to `total`;
  that is expected, not a rendering bug.
- `pass_rate` = `pass / (total - excluded)`, i.e. `excluded`-status rows are dropped from the
  denominator.
- `modules-suites` and `contrib-suites` are excluded from `pass_rate` entirely — both their own
  row (shown as `—`) and the overall total's rate — because they are Makefile-level `defer`
  roll-ups (one row per feature directory), not individually tracked pass/fail cases.
