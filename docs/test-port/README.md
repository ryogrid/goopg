# PostgreSQL Oracle Test-Port — single source of truth

This directory tracks the porting of upstream PostgreSQL 18.3 tests into goopg
as a compatibility oracle. The **one** authoritative data file is:

- [`postgres-oracle-target-inventory.csv`](postgres-oracle-target-inventory.csv)

Everything else in this directory is **derived from it** and must be regenerated
in the same commit that edits the CSV (`make regen-testport`).

## History

Until 2026-08-14 the porting state was split across three CSVs that duplicated
and drifted from each other (regress pass was 24 in the inventory vs 41 in the
baseline; 60 TAP rows lived in two files). They were consolidated into the one
inventory CSV:

- `postgres-oracle-port-status.csv` (governance roll-up) — **removed**
- `regress-diff-baseline.csv` (regress pass/fail baseline) — **removed**

## Schema

```
id, suite_id, kind, item_path, status, pass_required, deferred_to, rationale
```

| column | meaning |
|--------|---------|
| `id` | stable label (`P-001`, `AC-002`, …), empty for per-case rows without one |
| `suite_id` | regress-sql / regress-expected / isolation-specs / recovery-tap / subscription-tap / client-tools-tap / modules-suites / contrib-suites |
| `kind` | regress / isolation / tap / mixed |
| `item_path` | upstream path under `postgres/` (the join key) |
| `status` | see vocabulary below |
| `pass_required` | `yes` = part of the must-pass set; `no` otherwise |
| `deferred_to` | milestone/task reference for `defer` rows, `-` otherwise |
| `rationale` | human rationale; a `port` row must name its `TestPort_*`/`TestE2E_*` func |

### One row per logical regress case

`regress-sql` and `regress-expected` used to carry a row for the *same* case —
`sql/<name>.sql` and `expected/<name>.out` — which double-counted every regress
case in every derived report. The 232 duplicate `regress-expected` rows were
removed on 2026-08-20.

The invariant now: **a regress case that has a `.sql` file is tracked exactly
once, in `regress-sql`.** `regress-expected` holds only the 33 upstream
*alternate-output* files that have no `.sql` of their own — the
platform/encoding/collation variants pg_regress picks between (`char_1.out`,
`xml_2.out`, `collate.icu.utf8_1.out`, `float4-misrounded-input.out`, …).

Do not re-add an `expected/<name>.out` row for a case that already has a
`sql/<name>.sql` row; record its outcome on the `regress-sql` row instead.

## Status vocabulary

- `pass` / `failed` / `not-tried` — per-case execution outcome
- `port` / `defer` / `excluded` — governance decision
- **must-pass** = `pass_required == yes` (all `port` rows, regress/isolation `pass` rows)

## Promotion workflow (one-CSV rule)

When a deferred/failed case starts passing:

1. In `postgres-oracle-target-inventory.csv`, flip the row: `status` → `port`/`pass`,
   `pass_required` → `yes`, `rationale` names the Go test func, clear `deferred_to`.
2. `make regen-testport` (regenerates all derived docs below).
3. If the case was in `ci/batch/expected-failures.csv`, delete its row.
4. The nightly batch picks up the new must-pass set automatically.

## Validation

`make check-testport-inventory` (and the nightly testport stage) load the CSV and
reject a malformed row: bad status/pass_required vocabulary, an `excluded` row
marked must-pass, a `defer` row without `deferred_to`, a `port` row whose rationale
names no test func, or a duplicate id.

## Derived docs (regenerated by `make regen-testport`)

- `postgres-oracle-target-inventory.md` — suite-level roll-up (`cmd/gen-oracle-inventory`)
- `upstream-regress-coverage.md` — per-case regress classification (`cmd/gen-regress-coverage`)
- `upstream-isolation-coverage.md` — per-spec isolation classification (`cmd/gen-isolation-coverage`)
- `upstream-tap-coverage.md` — per-file TAP classification (`cmd/gen-tap-coverage`)
- `analysis/postgres-oracle-compatibility-report.md` — aggregate report (`cmd/gen-oracle-report`)
