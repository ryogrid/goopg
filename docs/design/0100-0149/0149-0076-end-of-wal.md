Status: in progress \(slices 1 and 2 landed; all 14 cases run\).

Upstream: `postgres/src/test/recovery/t/039_end_of_wal.pl`; `src/backend/access/transam/xlogreader.c`

Cluster.pm `emit_wal`, `advance_wal_out_of_record_splitting_zone`, `advance_wal_to_record_splitting_zone`,

## What the test does

After `pg_switch_wal()`, each of 14 cases emits WAL with `pg_logical_emit_message`, stops the server immediately,
writes a hand\-crafted XLogRecord or XLogPageHeaderData at a computed LSN in the segment file, and restarts. Crash
recovery must stop at the defect and log xlogreader.c's exact message: invalid record length, incorrect prev\-link,
incorrect resource manager data checksum, invalid magic number, unexpected pageaddr, invalid info bits, no contrecord
flag, invalid contrecord length.

## Slice 1 \(landed\)

- `TestPort_Recovery039EndOfWal` is a full transcription of the `.pl`, replacing the old shortcut that only listed
  segment files. It is an expected failure until the re\-port closes; inventory R\-039 stays `port`.
- `pg_settings` gains the four preset rows the test reads \(`block_size`, `segment_size`, `wal_block_size`,
  `wal_segment_size`\), with PG 18.3's exact values. They are build constants, so fixed rows are faithful.
- `pg_control_checkpoint()` exists as a table function \(misc/pg\_controldata.c\), read from pg\_control.

## Slice 2: pg\_switch\_wal \(landed\)

- `Writer.SwitchSegment` is RequestXLogSwitch. Under the same exclusive section as appendPGCompat's Path A, it:
  - drains the WAL buffer;
  - writes a header\-only XLOG\_SWITCH record \(RM\_XLOG\_ID, info 0x40\) and zero\-fills the rest of the segment in
    the same stream write. CopyXLogRecordToWAL zeros those pages too, headers included;
  - moves the insert position to the segment boundary with xl\_prev pointing at the switch record
    \(ReserveXLogSwitch\);
  - flushes, as XLogInsertRecord's WALINSERT\_SPECIAL\_SWITCH branch does.
- It returns the end of the switch record \(plus the page header it straddled\), or the boundary itself when the
  current segment is still empty and nothing is written \(ReserveXLogSwitch's early return\). `pg_switch_wal()`
  returns that LSN and refuses to run in recovery.
- Both of goopg's WAL walks — replay's `readAllPageAware` and the writer's startup position scan — step to the next
  segment boundary after an XLOG\_SWITCH \(XLogDecodeNextRecord\). Without that, the zero tail read as end of WAL.
- Checked with PG 18.3 pg\_waldump: the first record of the next segment shows `prev` = the switch record.
