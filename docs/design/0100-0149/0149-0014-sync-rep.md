# 0149-0014 — Port recovery/t/007\_sync\_rep.pl

Status: done.

Upstream: `postgres/src/test/recovery/t/007_sync_rep.pl`; syncrep.c `SyncRepGetCandidateStandbys`,
`SyncRepGetStandbyPriority`, `SyncRepGetSyncRecPtr`; walsender.c `pg_stat_get_wal_senders`; libpqwalreceiver.c
`fallback_application_name`.

## What the test checks

A primary with up to four standbys reports each standby's `sync_priority` and `sync_state` in
`pg_stat_replication`. The test sets `synchronous_standby_names` with ALTER SYSTEM and reloads it. It covers the old
comma list, `*`, `N(...)`, `num_sync` above the list length, `*` mixed with names, FIRST and ANY. It also stops and
restarts standbys so that ties between standbys of equal priority resolve by walsender slot order.

## Harness

- `TestPort_Recovery007SyncRep` in `internal/testport/recovery_007_sync_rep_test.go` runs three pairings: all\-goopg,
  PG 18.3 primary → goopg standbys, goopg primary → PG 18.3 standbys.
- Like Cluster.pm, `tapnode.Node.Start` passes `--cluster-name=<node>` on the command line, through a new
  `SetStartArgs` on both cluster harnesses. `Node.Reload` is `pg_ctl reload`.

## Fixes

- **Standby name.** goopg now registers `cluster_name` \(postmaster context\). `goopg start` accepts `-c NAME=VALUE`
  and `--cluster-name`, applied over the config files as command\-line settings. When primary\_conninfo names no
  application\_name, the walreceiver sends `cluster_name`, falling back to `walreceiver`.
- **PG's standby selection.** `SyncRep` now keeps walsender slots. A walsender takes the lowest free slot and frees it
  on exit.
  - A standby's priority is the 1\-based position of the first list member equal to its name \(case\-insensitive\)
    or `*`; under ANY every match is 1.
  - The candidates are the slots with a non\-zero priority and a reported flush position. Under FIRST, when there are
    more of them than `num_sync`, only the `num_sync` best by \(priority, slot\) are kept.
  - A commit is released when there are at least `num_sync` candidates and the oldest candidate position \(FIRST\)
    or the `num_sync`\-th latest \(ANY\) has reached it.
  - `pg_stat_replication` shows priority 0 / async until the standby reports a flush position. Candidates show sync
    \(FIRST\) or quorum \(ANY\); the rest show potential.
  - The parser no longer rejects `num_sync` greater than the list length.
- **Reload.** A SIGHUP re\-applies `synchronous_standby_names` \(PG's walsenders call `SyncRepInitConfig`\).

## Not covered

- Logical walsenders still use the name\-keyed `UpdateStandbyProgress` / `ForgetStandby` wrappers. Those claim a slot
  on the first reply rather than at connection, and `ForgetStandby` frees every slot with that name.
- The parser still takes `FIRST (a, b)` with no count as FIRST 1; PG's grammar requires the number.
- `cluster_name` is not checked for non\-ASCII characters \(`check_cluster_name`\) and is not used in process titles.
- A cascading walsender is not given priority 0.
