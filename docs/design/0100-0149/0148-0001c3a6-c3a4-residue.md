# M0148\-0001c3a6 — c3a4 residue: join OR bitmaps and array\-literal leftovers

Parent: M0148\-0001c3a4 \(design: 0148\-0001c3a4\-scalararrayop\-index\-residue
part 1 / part 2\).

## Item \(i\) slice 1 — cross\-type integer array literals as index quals

PG reference: match\_saopclause\_to\_indexcol \(indxpath.c\) — the
operator only has to be in the index column's opfamily. integer\_ops holds
the cross\-type `=` \(int24eq, int48eq, int84eq, …\).
\_bt\_preprocess\_array\_keys compares with the cross\-type ORDER proc, and
\_bt\_merge\_arrays intersects arrays on one column.

### The gap

- `unique1 = ANY ('{33,44}'::bigint[])` on an int4 column was refused:
  castIsColumnArrayType requires the literal's element type to equal the
  column's.
- The qual stayed a Filter, printed without its cast \(`'{33, 44}'`\),
  where PG merges it into the Index Cond.

### The fix

- **crossIntArrayLiteral:** accepts a cast array literal of another
  integer type \(int2 / int4 / int8\) as a column qual on an integer
  column \(saopColumnQuals\).
  - The probe keeps only the elements inside the column type's range. One
    outside can match no key; PG's exact cross\-type comparison finds it
    unequal to every value.
  - If none is inside, the array is empty and matches nothing.
- **SAOPColQual.ArrayText:** keeps the literal as PG prints the Const
  \(`'{33,4400000000}'::bigint[]`\); EXPLAIN renders it verbatim.

### Verification

- **Scratch PG:** plans and rows match for in\-range, mixed and
  all\-out\-of\-range elements, and for `int2col = ANY ('{2,3}'::int4[])`.
- **TestCrossTypeIntegerArrayColumnQual:** pins 2 plans and 3 row
  results; the plans fail with the arm disabled.
- **Regress:** create\_index 2708→2689.
- **Gates:**
  - units, tpch\-spotcheck, sf025 same=99;
  - fire\-set fires=none on sf025, sf1 and TPC\-H;
  - acceptance 24 MATCH.

### Not covered

- **Primary probe:** a cross\-type literal as the primary probe array
  \(nothing else on the column\) is still refused there. Only the
  column\-qual merge takes it.
- **Untyped literal on int2:** an untyped `'{1,2}'` on a smallint column
  prints `'{1,2}'::integer[]` where PG prints `smallint[]`.
  inListArrayConst cannot tell an `IN (1, 2)` list \(integer\) from an
  untyped array literal \(the column's type\).
- **Mixed\-type OR on a bitmap arm:** `tenthous = 1::int2 OR tenthous =
  3::int8 OR …` stays a Filter. PG makes a BitmapOr of an int2 equality
  arm and an `= ANY ('{3,42}'::bigint[])` arm.

## Item \(i\) slice 2 — cross\-type integer literals as plain index quals

PG reference:
- integer\_ops' cross\-type operators \(int48eq, int24lt, int48pl, …\);
- eval\_const\_expressions folds `3::int8` — and `-3::int8`, i.e.
  `-(3::int8)` — to an int8 Const;
- ruleutils get\_const\_expr prints a non\-int4 integer Const quoted and
  labelled \(`'3'::bigint`, `'1'::smallint`\).

### The gap

- `tenthous = 3::int8` on an int4 column printed `(tenthous = 3)`:
  formatCoercedLiteralOperands unwrapped the cast and coerced the literal
  to the column's type, which is right only where no cross\-type operator
  exists.
- The plain producer refused the key: restrictionKeyUsable admits a cast
  key only of the column's own type.
- The bitmap producer bound it but kept it as a Filter, so goopg planned
  `Bitmap … Recheck Cond: (thousand = 42) Filter: (tenthous = 3)` where PG
  plans `Index Scan … Index Cond: ((thousand = 42) AND (tenthous =
  '3'::bigint))`.

### The fix

- **EXPLAIN:** formatCrossIntLiteralOperands prints an explicitly cast
  integer literal against an integer operand of another width as its own
  Const, a negation folded in. indexCondClause uses it for index keys.
- **Keys:** restrictionKeyUsable admits such a key when its value fits the
  column's type \(crossIntCastKey\), and isIndexKeyOperand admits the
  negated form.
- **Statistics:** normalizeColumnConst / normalizeColumnConstRange read the
  literal as its integer Const \(integerCastLiteral\), so the estimate uses
  the column's statistics.
- **Bitmap:** the range collectors take it as a constant bound
  \(bitmapConstKey\). The bitmap equality collector no longer binds an
  out\-of\-range one, which could not be encoded into the column's key.

### Verification

- **Scratch PG:** equality, negated equality and range \(bitmap\) plans
  and estimates are identical; rows match.
- **TestCrossTypeIntegerLiteralIndexQual:** pins 4 plans and 3 row
  results; the plans fail with key admission disabled.
- **Regress:** create\_index 2689→2664, partition\_prune 6755→6754.
  - arrays moved \+13 once and reproduced at 3142 in two re\-runs; the
    diff is an `array_agg` ordering flake, ledgered.
- **Gates:**
  - units, tpch\-spotcheck, sf025 same=99;
  - fire\-set fires=none on sf025, sf1 and TPC\-H;
  - acceptance 24 MATCH;
  - TestPort\_Isolation ok.

### Not covered

- **Grouping OR arms by type:** PG's group\_similar\_or\_args turns
  `tenthous = 3::int8 OR tenthous = 42::int8` into one `= ANY
  ('{3,42}'::bigint[])` BitmapOr arm next to the int2 arm. goopg makes one
  arm per equality.
- **Out\-of\-range equality key:** `tenthous = 9999999999::int8` stays a
  Filter. PG's Index Scan probes it and finds nothing.
