# M0148\-0001c3a6 — c3a4 residue: join OR bitmaps and array\-literal leftovers

Parent: M0148\-0001c3a4 \(design: 0148\-0001c3a4\-scalararrayop\-index\-residue
part 1 / part 2\).

## Item \(i\) slice 1 — cross\-type integer array literals as index quals

PG reference: match\_saopclause\_to\_indexcol \(indxpath.c\) — the
operator only has to be in the index column's opfamily. integer\_ops holds
the cross\-type `=` \(int24eq, int48eq, int84eq, …\).
\_bt\_preprocess\_array\_keys compares with the cross\-type ORDER proc, and
\_bt\_merge\_arrays intersects arrays on one column.

### The gap

- `unique1 = ANY ('{33,44}'::bigint[])` on an int4 column was refused:
  castIsColumnArrayType requires the literal's element type to equal the
  column's.
- The qual stayed a Filter, printed without its cast \(`'{33, 44}'`\),
  where PG merges it into the Index Cond.

### The fix

- **crossIntArrayLiteral:** accepts a cast array literal of another
  integer type \(int2 / int4 / int8\) as a column qual on an integer
  column \(saopColumnQuals\).
  - The probe keeps only the elements inside the column type's range. One
    outside can match no key; PG's exact cross\-type comparison finds it
    unequal to every value.
  - If none is inside, the array is empty and matches nothing.
- **SAOPColQual.ArrayText:** keeps the literal as PG prints the Const
  \(`'{33,4400000000}'::bigint[]`\); EXPLAIN renders it verbatim.

### Verification

- **Scratch PG:** plans and rows match for in\-range, mixed and
  all\-out\-of\-range elements, and for `int2col = ANY ('{2,3}'::int4[])`.
- **TestCrossTypeIntegerArrayColumnQual:** pins 2 plans and 3 row
  results; the plans fail with the arm disabled.
- **Regress:** create\_index 2708→2689.
- **Gates:**
  - units, tpch\-spotcheck, sf025 same=99;
  - fire\-set fires=none on sf025, sf1 and TPC\-H;
  - acceptance 24 MATCH.

### Not covered

- **Primary probe:** a cross\-type literal as the primary probe array
  \(nothing else on the column\) is still refused there. Only the
  column\-qual merge takes it.
- **Untyped literal on int2:** an untyped `'{1,2}'` on a smallint column
  prints `'{1,2}'::integer[]` where PG prints `smallint[]`.
  inListArrayConst cannot tell an `IN (1, 2)` list \(integer\) from an
  untyped array literal \(the column's type\).
- **Mixed\-type OR on a bitmap arm:** `tenthous = 1::int2 OR tenthous =
  3::int8 OR …` stays a Filter. PG makes a BitmapOr of an int2 equality
  arm and an `= ANY ('{3,42}'::bigint[])` arm.

## Item \(i\) slice 2 — cross\-type integer literals as plain index quals

PG reference:
- integer\_ops' cross\-type operators \(int48eq, int24lt, int48pl, …\);
- eval\_const\_expressions folds `3::int8` — and `-3::int8`, i.e.
  `-(3::int8)` — to an int8 Const;
- ruleutils get\_const\_expr prints a non\-int4 integer Const quoted and
  labelled \(`'3'::bigint`, `'1'::smallint`\).

### The gap

- `tenthous = 3::int8` on an int4 column printed `(tenthous = 3)`:
  formatCoercedLiteralOperands unwrapped the cast and coerced the literal
  to the column's type, which is right only where no cross\-type operator
  exists.
- The plain producer refused the key: restrictionKeyUsable admits a cast
  key only of the column's own type.
- The bitmap producer bound it but kept it as a Filter, so goopg planned
  `Bitmap … Recheck Cond: (thousand = 42) Filter: (tenthous = 3)` where PG
  plans `Index Scan … Index Cond: ((thousand = 42) AND (tenthous =
  '3'::bigint))`.

### The fix

- **EXPLAIN:** formatCrossIntLiteralOperands prints an explicitly cast
  integer literal against an integer operand of another width as its own
  Const, a negation folded in. indexCondClause uses it for index keys.
- **Keys:** restrictionKeyUsable admits such a key when its value fits the
  column's type \(crossIntCastKey\), and isIndexKeyOperand admits the
  negated form.
- **Statistics:** normalizeColumnConst / normalizeColumnConstRange read the
  literal as its integer Const \(integerCastLiteral\), so the estimate uses
  the column's statistics.
- **Bitmap:** the range collectors take it as a constant bound
  \(bitmapConstKey\). The bitmap equality collector no longer binds an
  out\-of\-range one, which could not be encoded into the column's key.

### Verification

- **Scratch PG:** equality, negated equality and range \(bitmap\) plans
  and estimates are identical; rows match.
- **TestCrossTypeIntegerLiteralIndexQual:** pins 4 plans and 3 row
  results; the plans fail with key admission disabled.
- **Regress:** create\_index 2689→2664, partition\_prune 6755→6754.
  - arrays moved \+13 once and reproduced at 3142 in two re\-runs; the
    diff is an `array_agg` ordering flake, ledgered.
- **Gates:**
  - units, tpch\-spotcheck, sf025 same=99;
  - fire\-set fires=none on sf025, sf1 and TPC\-H;
  - acceptance 24 MATCH;
  - TestPort\_Isolation ok.

### Not covered

- **Grouping OR arms by type:** PG's group\_similar\_or\_args turns
  `tenthous = 3::int8 OR tenthous = 42::int8` into one `= ANY
  ('{3,42}'::bigint[])` BitmapOr arm next to the int2 arm. goopg makes one
  arm per equality.
- **Out\-of\-range equality key:** `tenthous = 9999999999::int8` stays a
  Filter. PG's Index Scan probes it and finds nothing.

## Item \(i\) slice 3 — OR arms of one integer type become one array

PG reference: indxpath.c group\_similar\_or\_args \(per \(index key,
operator\) groups\) and match\_orclause\_to\_indexcol. Every constant must
have one type, which is what makes it one ScalarArrayOp operator.

### The gap

- groupSimilarOrArgs already split `tenthous = 1::int2 OR tenthous =
  3::int8 OR tenthous = 42::int8` into the int2 arm and an int8 sub\-OR
  \(keyTypeTag keys on a cast's target type\).
- orEqualitySAOP accepted only plain literals, so the sub\-OR never became
  `= ANY ('{3,42}'::bigint[])`. Each arm was its own bitmap arm.

### The fix

- **orEqualitySAOP:** admits explicitly cast integer Consts
  \(bitmapConstKey\) and requires one keyTypeTag across the arms.
  - Without that check the plain producer merged the mixed\-type OR into
    one array, which PG never builds.
- **inListArrayConst:** prints a list of same\-type cast integer literals
  as the array Const of that type \(sameTypeIntCastList\).

### Verification

- **Scratch PG:** the witness plan is identical — BitmapOr of the int2 arm
  and the `= ANY ('{3,42}'::bigint[])` arm, the grouped Recheck Cond, and
  the original OR as Filter. Rows match.
- **TestCrossTypeIntegerLiteralIndexQual:** gains the plan and a row case.
- **Regress:** create\_index 2664→2637; arrays back at its baseline 3142,
  confirming slice 2's \+13 was the flake.
- **Gates:**
  - units, tpch\-spotcheck, sf025 same=99;
  - fire\-set fires=none on sf025, sf1 and TPC\-H;
  - acceptance 24 MATCH.

## Item \(i\) slice 4 — every range bound is an index clause

PG reference: match\_clause\_to\_indexcol takes every bound on the column
as an index clause. \_bt\_preprocess\_keys \(\_bt\_compare\_scankey\_args\)
keeps the tightest per direction at run time, and Index Cond prints them
all in restriction order.

### The gap

- restrictionRangeOnColumnLocal kept the first lower and the first upper
  bound, and left the rest as Filters: `Index Cond: (unique1 < 3) Filter:
  (unique1 < '-1'::bigint)`.
- saopColumnQuals and trailingColumnQuals took plain literals only, so a
  cast integer bound stayed a Filter behind an array.

### The fix

- **tightestIntBound:** when a direction has several bounds and every key
  is an integer Const \(plain or a cast literal\), the tightest drives the
  probe — the largest lower, the smallest upper, strict over non\-strict
  on a tie. The others become redundantBound clauses: dropped from the
  Filter, counted in selectivity as PG counts them, and sorted with the
  probe bounds into restriction order. Otherwise first\-wins stays.
- **Lowering:** IndexScan and IndexOnlyScan lower redundant clauses onto
  ExtraBounds with an IndexCondExtraBound order item.
- **Rendering:** rangeCondWithExtraBounds splices the ExtraBounds into the
  range column's Index Cond.
- **Bitmap and behind\-array consumers:** skip redundant clauses, so those
  conjuncts stay Filter / Recheck there.
- **Column quals:** saopColumnQuals and trailingColumnQuals admit cast
  integer bounds \(bitmapConstKey\).

### Verification

- **Scratch PG:** the five witness queries are identical, rows included.
- **TestRedundantRangeBoundsInIndexCond:** pins 3 plans and 4 row
  results; the redundant\-bound plans fail with the arm disabled.
- **Regress:** create\_index 2637→2535, only removed divergences.
- **Gates:**
  - units, tpch\-spotcheck, sf025 same=99;
  - fire\-set fires=none on sf025, sf1 and TPC\-H;
  - acceptance 24 MATCH;
  - TestPort\_Isolation ok.

### Not covered

- **Non\-comparable keys:** bounds on params or non\-integer types keep
  first\-wins; their extras stay Filters.
- **Other consumers:** bitmap scans, the bound behind an array, and a
  leading NullTest beside several bounds do not print the redundant
  bounds in Index Cond.

## Item \(i\) slice 5 — an equality beside the leading array merges into it

PG reference:
- build\_index\_paths gives the index one clause set holding both `col =
  ANY (…)` and `col = const`;
- \_bt\_preprocess\_keys \(\_bt\_compare\_array\_scankey\_args\) keeps the
  matching element;
- the equality, an EquivalenceClass member, is regenerated after the other
  quals \(generate\_base\_implied\_equalities\), so Index Cond prints it
  after the array whatever its source position.

### The gap

- restrictionEqualityPrefix bound `unique1 = 1` and the array stayed a
  Filter: `Index Cond: (unique1 = 1) Filter: (unique1 = ANY (…))`.
  The bitmap producer did the same.

### The fix

- **saopColumnQuals:** admits `col = const` as a column qual, ordered
  after every non\-equality qual and after the array.
- **equalityMergedIntoLeadingSAOP:** when the equality prefix is that one
  column and the leading array merges its equality, the restriction,
  index\-only and bitmap producers drop the prefix and file the array
  path.

### Verification

- **Scratch PG:** single\-column cases are identical, rows included
  \(matching, non\-matching, plain Index Scan\).
- **TestEqualityMergedIntoLeadingArray:** pins 2 plans and 3 row results;
  the plans fail with the helper disabled.
- **Regress:** create\_index 2535→2500.
- **Gates:**
  - units, tpch\-spotcheck, sf025 same=99;
  - fire\-set fires=none on sf025, sf1 and TPC\-H;
  - acceptance 24 MATCH;
  - TestPort\_Isolation ok.

### Not covered

- **Multi\-column prefix:** `thousand IN (1, 42) AND thousand = 42 AND
  tenthous = 42` keeps the equality prefix, where PG prints `((thousand =
  ANY …) AND (thousand = 42) AND (tenthous = 42))`. That needs an equality
  behind the array on the next column \(today only bounds ride there\).
