## 7. Bench and process hygiene, learned the expensive way

- **Never `pkill -f goopg`** — it self-matches the invoking shell (exit 144).
  Stop via `goopg stop -D <dir>` or the lifecycle scripts.
- **Give every concurrent agent a private clone + a 55xx port + its own
  `GOOPG_CG_UNIT`.** `flock` does not prevent collisions: the lock is
  advisory and `stop -D <datadir>` targets the data directory, not the port.
  A peer's `stop -D` has killed another agent's gate mid-run and produced an
  arm silently measured against the wrong binary.
- **Always start through `scripts/goopg-test-run.sh`** for the memory cap. An
  uncapped subagent server reached 30 GB RSS on a planner loop.
- **Hold server age constant in any A/B.** A server that just ran a heavy
  query sits at GOMEMLIMIT with GOGC=off and thrashes — "sweep-tail
  collapse" mimics a regression. `timeout N psql` kills only the client; the
  server keeps executing, so reap orphans between arms.
- **Agent waiting is the recurring pathology.** Five distinct failure forms
  have been seen: `tail -f | grep` never returning; unbracketed `pgrep`
  self-matching; *bracketed* `pgrep` still matching peers; polling only for
  a success token so a failure hangs forever; and `until [ -f
  /tmp/some-sentinel ]` on a sentinel nothing creates — that last one ran 24
  minutes before it was killed, and an agent blocked that way cannot receive
  messages, so queued instructions never arrive. Block on a real condition or
  finish and report.
