## The MCV "1.25×" question — definitive answer

**Doc 03 is right. Docs 06/07/08 agree with it. Nothing in the bundle needs to
change on this point, and the review brief's premise was inverted.**

Doc 03 does **not** claim PostgreSQL uses a 1.25× rule. Both places it appears
say the opposite:

- §2.5 (line 362): "the older rule `freq > 1.25 × average frequency`
  (PostgreSQL ≤ 11) **no longer exists in 18.3**".
- checklist #38 (line 1364): "MCVs are pruned … using a hypergeometric
  `2·stddev + 0.5` test against the non-MCV selectivity; **no 1.25× rule exists
  in 18.3**".

Docs 06/07/08 cite doc 03 checklist #38 *approvingly* as the reason goopg's
`mcvFreqMargin = 1.25` is a defect (`06:1782`, `07:368`, `08:266`, `TODO P1-08`).
There is no contradiction to resolve.

### What 18.3 actually does

`analyze_mcv_list` (`src/backend/commands/analyze.c:2980`, declared `:1879`,
called from `compute_scalar_stats` `:2697` and `compute_distinct_stats` `:2332`):

```c
if (samplerows == totalrows || totalrows <= 1.0) return num_mcv;   /* keep all */
ndistinct_table = stadistinct; if (< 0) ndistinct_table = -stadistinct * totalrows;
sumcount = Σ mcv_counts[0 .. num_mcv-2];
while (num_mcv > 0) {
    selec = 1.0 - sumcount/samplerows - stanullfrac;  clamp to [0,1];
    otherdistinct = ndistinct_table - (num_mcv - 1);
    if (otherdistinct > 1) selec /= otherdistinct;
    N = totalrows; n = samplerows; K = N * mcv_counts[num_mcv-1] / n;
    variance = n*K*(N-K)*(N-n) / (N*N*(N-1));  stddev = sqrt(variance);
    if (mcv_counts[num_mcv-1] > selec*samplerows + 2*stddev + 0.5) break;  /* keep */
    num_mcv--;  if (num_mcv == 0) break;  sumcount -= mcv_counts[num_mcv-1];
}
return num_mcv;
```

It is a **top-down prune from the least common entry**, using the lower end of a
continuity-corrected Wald-type confidence interval on a **hypergeometric**
sample count (the source's own words, `analyze.c:3046-3058`): keep the entry iff
its sample count exceeds the count it would be predicted to have *as a non-MCV*
by 2 standard deviations plus 0.5. Crucially the comparison baseline is the
**residual** non-MCV frequency (`1 − Σ MCV freqs − nullfrac`, divided by the
remaining distinct count), **not** the overall average frequency — the source
comment at `:3009-3018` explains this was the whole point of the change.

`grep -n '1\.25\|mincount' src/backend/commands/analyze.c` returns **zero
hits** in 18.3.

### Where 1.25 came from

Commit `b5db1d93d2a6e2d3186f8798a5d06e07b7536a1d`, 2018-03-22, "Improve
ANALYZE's strategy for finding MCVs", first released in PG 11. Its own message:
*"Previously, a value was included in the MCV list if its frequency was 25%
larger than the estimated average frequency of all nonnull values in the
table."* That is the `mincount = avgcount * 1.25` (floored at 2) test. It has
not existed since.

**Conclusion:** goopg's `mcvFreqMargin = 1.25` (doc 06 §2.5) is genuinely
non-PG-18 behaviour, and the gap rows in 07/08/TODO are correct as written.
Doc 03's only defect on this topic is the parenthetical "(PostgreSQL ≤ 11)",
which should read "(PostgreSQL ≤ 10)" — logged as MINOR above.
