### Additional defect the docs understate (not a doc error — a code finding)

`numericValue`'s type switch lists `"int","int2","int4","int8","smallint","integer","bigint","numeric","decimal","float","real","double precision"`. goopg canonicalises type names to PG internal spellings — `double precision`/`float(25)` → `float8`, `real`/`float(1..24)` → `float4` (`internal/parser/float_typename_test.go:9-38`). **`float4` and `float8` are not in the switch**, so a `real` or `double precision` column takes the same flat-0.5 `bucketFraction` path and the same byte-wise `histCmp` fallback that 05/06/07 attribute only to date/timestamp/text/bool. The docs' enumeration ("`date`, `timestamp`, `text`, `varchar`, `char`, `bool`") is therefore incomplete; float columns belong on that list.
Citation: `internal/optimizer/selectivity.go:289` `numericValue`, consumed at `:233` `bucketFraction` and `:269` `histCmp`.
