# 0096-0012 — CREATE TRIGGER + PL/pgSQL Trigger Execution

**Status:** accepted  
**Date:** 2026-05-12  
**Milestone:** M0096-0012

## Problem

Isolation test specs (`eval-plan-qual-trigger`, `partition-key-update-3/4`,
`fk-snapshot`) use `CREATE TRIGGER … FOR EACH ROW EXECUTE FUNCTION/PROCEDURE`.
Without trigger support:
- `CREATE TRIGGER` raised a parse error.
- Functions declared `RETURNS TRIGGER` failed to parse (`TRIGGER` was not a
  recognised type name).
- PL/pgSQL bodies containing `INSERT …`, `RAISE NOTICE …`, and `OLD.col`
  references failed to parse or execute.

## Solution

### Parser (internal/parser/)

**token.go** — New `KwTrigger` keyword ("trigger"); classified
`KwCatUnreserved` so it is usable as an identifier.

**ast.go** — `TriggerTiming` type (Before/After/InsteadOf) + `CreateTriggerStmt`
(Name, Table, Timing, Events, ForEachRow, FuncName) + `DropTriggerStmt`.

**ddl.go** — `parseCreateTriggerTail`: parses the full trigger DDL syntax
including BEFORE/AFTER/INSTEAD OF, event list, FOR [EACH] ROW|STATEMENT,
optional WHEN clause (skipped), and EXECUTE {FUNCTION|PROCEDURE} funcname().
`parseDropTriggerTail`: IF EXISTS + trigger name + ON table.
`parseCreate` and `parseDrop` dispatch tables updated.
`RETURNS TRIGGER` now accepted automatically because `TRIGGER` is an unreserved
keyword accepted by `parseColumnType()` / `parseIdent()`.

### Catalog (internal/catalog/)

**catalog.go** — `TriggerTiming` type + `Trigger` struct (Name, TableOID,
Timing, Events, ForEachRow, FuncName, FuncSchema). `Triggers []Trigger` added
to `Table`.

### Executor DDL (internal/executor/operators_ddl.go)

`execCreateTrigger` registers the trigger in `tbl.Triggers`, replacing any
existing entry with the same name. `execDropTrigger` removes it. Both are
dispatched from the main DDL switch.

### PL/pgSQL Extensions (internal/plpgsql/)

**ast.go** — Two new statement types:
- `SQLStmt{SQL string}`: embedded SQL DML/query (INSERT, UPDATE, DELETE,
  SELECT). Raw SQL text stored verbatim.
- `RaiseStmt{Level, Msg string}`: RAISE NOTICE/WARNING/ERROR/EXCEPTION.

**parser.go** — New parse functions:
- `parseSQLStmt`: scans to `;`, stores raw SQL in a `SQLStmt`.
- `parseRaise`: recognises RAISE + optional level ident + message text.
- `parseDottedExprStmt`: called when `parseAssign` sees `ident.field`; scans
  to `;` and emits a no-op `AssignStmt{Target: "_plpgsql_noop"}`.
- `parseAssign` extended to also accept `=` (not just `:=`) as the assignment
  operator; dotted targets (`OLD.b = …`) route to `parseDottedExprStmt`.
- `parseStmt` switch extended for `KwInsert`/`KwUpdate`/`KwDelete`/`KwSelect`
  → `parseSQLStmt`, and `raise` identifier → `parseRaise`.

### Executor — PL/pgSQL Runtime (internal/executor/plpgsql_runtime.go)

`plpgsqlFrame` gets a `trig *plpgsqlTrigCtx` field. The trigger context holds
OldRow, NewRow, table Columns, and TG_* string values.

`injectTriggerVars`: at trigger function entry, injects column values as
`_old_<colname>` / `_new_<colname>` frame variables, and `tg_name`, `tg_when`,
`tg_op`, `tg_level`, `tg_table_name` / `tg_relname` string variables.

`lowerPLpgSQLExpr` extended: `ColumnRef{Table: "old"/"new"}` lookups use the
pre-injected `_old_<colname>` / `_new_<colname>` frame variables.

`executePLpgSQLStmt` extended for three new node types:
- `RaiseStmt`: NOTICE/WARNING/INFO/LOG/DEBUG are no-ops; ERROR/EXCEPTION
  surfaces as SQLSTATE P0001.
- `SQLStmt`: calls `execPLpgSQLEmbeddedSQL`.
- `AssignStmt{Target: "_plpgsql_noop"}`: silently discarded.

`ReturnStmt` in trigger context: bare `ColumnRef{Column: "old"/"new"}` emits
`flowReturnTriggerOld` / `flowReturnTriggerNew` control-flow signals (new
enum values added); `NullConst` emits `flowReturnTriggerNull`.

`executePLpgSQLTriggerBody(r, trigCtx, ctx)`: new entry point for trigger
execution. Builds a trigger-enabled frame, executes the body, and interprets
the three new control-flow signals:
- `flowReturnTriggerOld` → return OldRow
- `flowReturnTriggerNew` → return NewRow
- `flowReturnTriggerNull` → return nil (row suppressed)

`execPLpgSQLEmbeddedSQL`: parses and executes embedded SQL after calling
`substituteTriggerRefs` to replace OLD.*/NEW.*/OLD.col/NEW.col with SQL
literals. Executes via `planner.Plan` + `Build` + operator drain.

`substituteTriggerRefs`: textual substitution for `OLD.*` → comma-separated
literal values and `OLD.colname` → single literal.

### Executor — Trigger Firing (internal/executor/operators_trigger.go, new)

`fireTriggers(ctx, tbl, timing, event, oldRow, newRow) (Row, bool)`: iterates
`tbl.Triggers`, finds matching entries via `triggerMatchesEvent`, looks up the
routine via `lookupTriggerRoutine`, and calls `executePLpgSQLTriggerBody`.
Returns the (possibly modified) new row and a bool (false = skip the row).
Currently only row-level triggers are supported.

### Executor — DML Hooks (internal/executor/operators_storage.go)

`insertOp.Next`: fires BEFORE INSERT triggers on the plan table's trigger list
before the FK check and heap write.

`deleteOp.Next`: fires BEFORE DELETE triggers on each victim row in a new
filtering loop (victims where the trigger returns NULL are removed from the
deletion set); FK enforcement follows in the same loop.

## Limitations (v0)

- AFTER triggers are wired into `fireTriggers` but are currently called from
  DML operators only in the BEFORE position; AFTER hook points are not yet
  added to insertOp/deleteOp (the BEFORE path is sufficient for
  partition-key-update-4).
- RAISE NOTICE message format strings (e.g. `'trig_report: % % % %'`) are not
  interpolated — NOTICE is a no-op so `eval-plan-qual-trigger`'s output will
  differ from expected.
- Statement-level triggers (FOR EACH STATEMENT) are parsed and stored but
  silently skipped at fire time.
- INSTEAD OF triggers on views are parsed but not fired.
- `ON UPDATE` trigger firing is not yet wired into `updateOp`.
