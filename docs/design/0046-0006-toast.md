# 0046-0006 — TOAST: out-of-line storage for wide columns

**Status:** draft
**Date:** 2026-05-04
**Milestone:** 0046 — Heap & MVCC maturation
**Supersedes:** —

## Context

A page in goopg is 8 KB. A row that does not fit on a page today causes
`heapInsert` to error out: there is no out-of-line storage. Real
schemas with `text` / `bytea` / `jsonb` columns routinely produce rows
that exceed 8 KB. PostgreSQL solves this with TOAST (The
Oversized-Attribute Storage Technique): a per-user-table TOAST relation
of small chunks that big columns get split into.

This is the smallest of the six M0046 sub-features but it has wide
ramifications — every tuple-codec read has to detect a TOAST pointer
and detoast on demand.

## Plan

1. **varlena header refresh.** `internal/access/heap` already has a
   length-prefixed datum encoding; extend it to upstream's two-shape
   format:
   - 1-byte short header for ≤ 126 bytes (high bit clear, length in
     low 7 bits).
   - 4-byte long header for `> 126` bytes; first bit pair encodes
     in-place vs out-of-line vs compressed.
2. **TOAST relation.** When a user table contains a TOAST-able column,
   `CREATE TABLE` (M0030) auto-creates `pg_toast.pg_toast_<reloid>` with
   columns `(chunk_id oid, chunk_seq int4, chunk_data bytea)` and a
   unique index on `(chunk_id, chunk_seq)`.
3. **Insert path.** When a tuple's serialised size exceeds
   `TOAST_TUPLE_THRESHOLD` (~ 2 KB), `internal/access/heap/toast.go`:
   - Picks the largest TOAST-able column.
   - Slices into ≤ `TOAST_MAX_CHUNK_SIZE` (~ 1996 bytes) chunks.
   - Inserts each chunk into the TOAST relation under a freshly-allocated
     `chunk_id` (toast_oid).
   - Replaces the original column value with a TOAST pointer
     `(toast_relid, value_size, chunk_id)`.
   - Repeats until the main tuple fits below the threshold.
4. **Read path.** Datum-decode boundary in the executor's expression
   evaluator handles "this datum is a TOAST pointer" — call
   `detoast(ptr)` lazily, and cache the result in the executor's
   per-row scratch.
5. **Delete path.** When a TOASTed row is reclaimed (HOT prune or
   VACUUM), enqueue its toast_oid for delete from the TOAST relation.
   Keep simple: synchronous within the same VACUUM pass.
6. **Compression** (pglz only for v0): if a value is ≥
   `TOAST_TUPLE_TARGET` and compresses to ≥ 25% smaller, store the
   compressed form (set the compression bit in the TOAST header).
   LZ4 / ZSTD deferred.

## Definition of Done

- Insert + select round-trip of a 1 MiB `text` column.
- Random-access into a TOASTed `bytea` (substring) does not detoast the
  whole value — uses the per-chunk index. (Upstream optimisation; nice-to-
  have for v0, can be deferred.)
- TOAST relation auto-created at `CREATE TABLE` time when a column type
  is TOAST-able.
- VACUUM of the parent relation cleans up orphaned TOAST chunks.
